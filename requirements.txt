# Pinned deliberately. This file used to be completely unpinned, so every
# Streamlit Cloud rebuild re-resolved the whole tree to the newest releases -
# meaning a breaking release anywhere could take the live app down with no code
# change on our side.
#
# ---------------------------------------------------------------------------
# The starlette pin below is load-bearing. Do not remove it without testing.
# ---------------------------------------------------------------------------
# Symptom it fixes:
#   TypeError: GZipResponder.__init__() missing 1 required keyword-only
#   argument: 'thread_minimum_size'
#
# Traced by diffing starlette releases: `thread_minimum_size` became a REQUIRED
# keyword-only argument on GZipResponder.__init__ in starlette 1.4.0. Every
# version up to and including 1.3.1 is clean.
#
# Streamlit is what breaks: it subclasses starlette's GZipResponder in
# streamlit/web/server/starlette/starlette_gzip_middleware.py and constructs it
# without that argument. Streamlit 1.61.0 declares `starlette<2,>=0.46.0`, and
# that upper bound is too loose - pip happily installs 1.4.0 and the server dies
# on the first gzip-accepting request. Nothing in this repo touches gzip or
# starlette; it arrives via streamlit itself.
#
# Revisit once Streamlit ships a release compatible with starlette >= 1.4.

# --- core app ---
streamlit>=1.40,<2
starlette>=0.46,<1.4        # see the note above - anything >= 1.4 breaks streamlit's gzip middleware
pandas>=2.0,<3
numpy>=1.24,<3
openpyxl>=3.1,<4
XlsxWriter>=3.1,<4          # pd.ExcelWriter(engine='xlsxwriter') in the weekly scripts

# --- ESPN + parsing ---

# --- streamlit components used by the pages ---
